0. Principios de ingeniería
MARTIS se construirá alrededor de una premisa: el motor biológico debe poder ejecutar una simulación marciana completa sin necesitar Godot, una interfaz gráfica ni un dispositivo de renderizado.
El proyecto tendrá dos productos técnicos diferenciados:
MARTIS Simulation: motor científico que calcula el mundo.
MARTIS Game: aplicación interactiva que permite configurar, observar y controlar ese mundo.
La separación permitirá ejecutar experimentos automatizados, pruebas científicas, benchmarks y simulaciones de larga duración desde una aplicación de consola.

3. Modelos matemáticos y algoritmos
Los modelos iniciales priorizan velocidad, causalidad y balances verificables. No pretenden reproducir toda la complejidad biológica de Marte o de la Tierra.
3.1 Convenciones
Las cantidades físicas no serán negativas.
Los recursos consumidos no superarán los disponibles.
La biomasa no aparecerá sin fuente de materia.
La energía no se creará gratuitamente.
Las tasas tendrán unidad temporal explícita.
Las probabilidades estarán en [0,1].
Paso temporal inicial: Δt = 1 sol, aproximadamente 88.775 segundos terrestres. Es una decisión de discretización, no una afirmación de que todos los procesos biológicos ocurran diariamente.
3.2 Ambiente
Temperatura regional: T(x,y,t) = T_base(x,y) + D(t) + S(t) + ε. D(t) puede aproximarse con A_d cos(2πt/P_d + φ); S(t), con A_s cos(2πt/P_s + θ). Son componentes de un modelo de juego que requieren calibración local.
Radiación efectiva: R_efectiva = R₀ e^(−μz), donde R₀ es radiación incidente, μ un coeficiente efectivo y z profundidad/espesor protector. UV e ionizante no compartirán necesariamente el mismo coeficiente.
Agua accesible: W_disponible = W_total · f_accesibilidad. La función dependerá de temperatura, estado físico, salinidad, potencial hídrico y condiciones locales. Hielo no equivale a agua metabólicamente disponible.
3.3 Estrés ambiental
Curva térmica gaussiana: f_T(T) = exp(−(T−T_opt)²/(2σ_T²)). Radiación: f_R(R) = 1/(1+αR). Agua: f_W(W) = W/(K_W+W).
Factor agregado: F_environment = f_T · f_R · f_W · f_P · f_N. El producto es una abstracción inicial; las interacciones biológicas reales pueden ser más complejas.
3.4 Metabolismo
public sealed record ReactionDefinition(
    ReactionId Id,
    IReadOnlyDictionary<string, double> Inputs,
    IReadOnlyDictionary<string, double> Outputs,
    double MaximumRate,
    double EnergyYield,
    string RequiredCapability
);
Las reacciones se expresarán con coeficientes de entrada y salida. Una tabla conceptual CO₂ + agua → carbono orgánico + oxígeno solo ilustra el flujo y NO representa una reacción completa balanceada.
Velocidad inicial: v = v_max · F_T · F_R · F_W · F_E. Para cada sustrato: F_i = C_i/(K_i+C_i). En varios recursos limitantes: F_sustrato = min(F₁,F₂,…,Fₙ).
Energía neta: E_neta = E_producida − E_mantenimiento − E_reproducción. Prioridad de asignación: mantenimiento, reparación, reserva energética, crecimiento y reproducción.
3.5 Crecimiento y mortalidad
Modelo logístico modificado: N_(t+1) = N_t + r_efectivo N_t (1 − N_t/K). r_efectivo = r_max · F_environment · F_metabolism. K = min(K_W,K_C,K_N,K_P,K_E), pero esta capacidad no debe crear recursos adicionales.
Mortalidad combinada: m = 1 − ∏ᵢ(1−mᵢ). Supervivientes: N_s = N(1−m). Los términos pueden incluir estrés térmico, radiación, agua, nutrientes, energía y competencia.
3.6 Competencia y reciclaje
Cuando la demanda total supera disponibilidad, asignación proporcional: C_i_asignado = C_total · D_i/(Σ_j D_j). La implementación inicial evita que cada población consuma como si el depósito compartido no hubiera sido utilizado.
Biomasa muerta: B_muerta = B_inicial − B_superviviente. Materia orgánica: O_(t+1) = O_t + k_d B_muerta − U_O. La descomposición devuelve recursos a depósitos correspondientes, conservando elementos según resolución del modelo.
4. Genética y evolución
4.1 Representación y herencia
Genome A01
├── UV_PROTECTION          0.80
├── THERMAL_TOLERANCE      0.65
├── DESICCATION_TOLERANCE  0.90
├── PHOTOSYNTHESIS         0.70
├── REPAIR_CAPACITY        0.55
├── REPRODUCTION_RATE      0.40
└── BIOFILM_PRODUCTION     0.30
MVP: herencia clonal con mutación. El descendiente hereda el genoma parental salvo cambios mutacionales. Recombinación y transferencia horizontal se dejan para después.
4.2 Mutación
Probabilidad por rasgo: P(mutación)=μ. Si ocurre: g′=g+δ, con δ ~ Normal(0,σ²), y g′=clamp(g′,0,1). μ y σ son parámetros configurables de juego y no tasas moleculares reales.
Las variantes se representan dividiendo la población agregada. Ejemplo ilustrativo: 10.000 individuos → variante A 9.900 y variante B 100. No implica una tasa biológica real.
4.3 Selección natural y deriva
Éxito relativo: wᵢ=sᵢrᵢ, con supervivencia sᵢ y reproducción efectiva rᵢ. Frecuencia posterior: pᵢ′=pᵢwᵢ/(Σⱼpⱼwⱼ). El número absoluto de descendientes sigue limitado por recursos.
La deriva genética se aproximará mediante muestreo estocástico (multinomial o binomial secuencial). El tamaño efectivo será parámetro separado de la abundancia agregada.
4.4 Gestión de variantes
Crear variante cuando exista diferencia genética funcional significativa.
Fusionar variantes equivalentes dentro de una tolerancia.
Eliminar poblaciones sin abundancia o biomasa.
Limitar variantes activas por especie y celda.
Conservar variantes raras cuando tengan importancia evolutiva configurable.
Límite inicial sugerido: 32 variantes por especie y celda. Es una decisión de rendimiento, no biológica.

5.5 Implementación base del motor
public sealed class SimulationEngine : ISimulationEngine
{
    private readonly IReadOnlyList<ISimulationSystem> _systems;
    private readonly SimulationRandom _random;
    private readonly SimulationConfiguration _configuration;
 
    public SimulationState State { get; private set; }
    public long CurrentTick => State.Tick;
 
    public SimulationEngine(
        SimulationState initialState,
        SimulationConfiguration configuration,
        SimulationRandom random,
        IReadOnlyList<ISimulationSystem> systems)
    {
        State = initialState;
        _configuration = configuration;
        _random = random;
        _systems = systems;
    }
 
    public void Initialize(SimulationConfiguration configuration)
        => configuration.Validate();
 
    public void Advance(int steps)
    {
        if (steps < 0)
            throw new ArgumentOutOfRangeException(nameof(steps));
 
        for (var i = 0; i < steps; i++)
        {
            var context = new SimulationContext(
                State, _random, _configuration,
                _configuration.DeltaTimeDays);
 
            foreach (var system in _systems)
                system.Execute(context, _configuration.DeltaTimeDays);
 
            State.Tick++;
        }
    }
 
    public void ApplyCommand(ISimulationCommand command)
        => command.Apply(State);
 
    public SimulationSnapshot CreateSnapshot()
        => SimulationSnapshot.FromState(State);
 
    public void Restore(SimulationSnapshot snapshot)
        => State = snapshot.ToState();
}
La inicialización definitiva deberá validar que sistemas, configuración y estado pertenecen a la misma versión del modelo.
6. Aleatoriedad determinista
La simulación debe poder reproducirse con la misma semilla, configuración, orden de comandos y versión de motor. No se repartirá System.Random por los sistemas.
public interface IRandomSource
{
    ulong NextUInt64();
    double NextDouble();
    int NextInt(int minInclusive, int maxExclusive);
    bool NextBool(double probability);
}
 
public sealed record RandomState(ulong State, ulong Increment);
Recomendación: PCG32 o PCG64 con versión del algoritmo fijada. Secuencias independientes: Environment RNG, Mutation RNG, Reproduction RNG, Genetic Drift RNG y Events RNG. Así una nueva llamada aleatoria en un sistema no desplaza todas las secuencias posteriores de los demás.
Guardar el estado interno del generador en snapshots. Para reproducibilidad estricta: fijar PRNG, versión de motor, orden de iteración, evitar GetHashCode() como semilla, evitar paralelismo no determinista, registrar versiones de datos y considerar aritmética reproducible en sistemas críticos.
Determinismo entre ejecuciones no garantiza idéntico resultado entre arquitecturas y versiones del runtime. El multithreading se incorporará solo después de demostrar que no altera los resultados.
7. Particionado espacial y rendimiento
MVP: cuadrícula 64 × 64 = 4.096 celdas. Cada celda representa una superficie regional abstracta. No se fija aún metros por celda: una celda de 1 m² y otra de 1 km² requieren modelos ambientales diferentes.
7.1 Índices
Índice lineal: index = y · width + x; para 64 × 64: index = y · 64 + x.
public readonly struct GridIndex
{
    public const int Width = 64;
    public const int Height = 64;
    public readonly int X;
    public readonly int Y;
 
    public GridIndex(int x, int y)
    {
        if (x < 0 || x >= Width || y < 0 || y >= Height)
            throw new ArgumentOutOfRangeException();
        X = x;
        Y = y;
    }
 
    public int ToLinearIndex() => Y * Width + X;
}
Almacenamiento principal mediante arrays y estructuras compactas, no diccionarios complejos para recorrer todas las celdas cada tick.
7.2 Sectores
Preparación para sectores de 16 × 16 celdas: 16 sectores en el mapa 64 × 64. Facilita actualización selectiva, paralelismo futuro, regiones activas, persistencia incremental y mapas mayores. No exige multithreading desde el inicio.
7.3 Difusión
Difusión discreta: C_i^(t+1)=C_i^t + DΔt Σ_(j∈N(i))(C_j^t−C_i^t). Para cuadrícula uniforme y esquema explícito de cuatro vecinos, condición orientativa de estabilidad: DΔt/Δx² ≤ 1/4. Si no se cumple, usar subpasos o integrador distinto. En MVP puede limitarse a agua superficial conceptual y algunos nutrientes.

9.3 Contenido de snapshot y recuperación
Tick, estado ambiental, poblaciones, genomas, recursos y estadísticas acumuladas.
Estado del PRNG y versiones del motor/datos.
Payload binario versionado y comprimido, si el benchmark lo justifica.
Al cargar: leer metadatos, comprobar compatibilidad, recuperar último snapshot válido, comprobar checksum, deserializar, restaurar RNG, validar invariantes y reanudar.
Si un snapshot está corrupto, intentar recuperar el anterior.
Versionado: motor, esquema, definiciones biológicas, parámetros científicos, semilla y algoritmo PRNG. Compatibilidad de carga no equivale a reproducibilidad histórica.

10.1 Conservación elemental
Cada reacción química deberá balancearse por elemento. Con matriz estequiométrica S y matriz de composición elemental A, se exige A·S=0. No se permitirán reacciones que creen C, H, O, N u otros elementos sin fuente.
Balance: M_final = M_inicial + M_entradas − M_salidas. Error: ε_M = |M_final − M_esperada|. Tolerancia combinada: ε_M ≤ ε_abs + ε_rel |M_esperada|. La tolerancia debe depender de escala y precisión numérica.
Registrar energía capturada, convertida, utilizada, disipada y almacenada. No hace falta representar todas las formas físicas en MVP, pero no se permite producción sin fuente.

12.2 Estado del mundo
public sealed class SimulationState
{
    public long Tick { get; set; }
    public EnvironmentState[] Environment { get; }
    public ResourcePool[] Resources { get; }
    public List<Population> Populations { get; }
    public SimulationStatistics Statistics { get; }
 
    public SimulationState(int width, int height)
    {
        var count = checked(width * height);
        Environment = new EnvironmentState[count];
        Resources = new ResourcePool[count];
 
        for (var i = 0; i < count; i++)
        {
            Environment[i] = new EnvironmentState();
            Resources[i] = new ResourcePool();
        }
 
        Populations = new List<Population>();
        Statistics = new SimulationStatistics();
    }
}
En versión optimizada, los estados ambientales podrán almacenarse en arrays de estructuras compactas para mejorar localidad de memoria. Esta primera versión prioriza claridad.
12.3 Sistema metabólico (esqueleto)
public sealed class MetabolismSystem : ISimulationSystem
{
    public void Execute(SimulationContext context, double deltaTime)
    {
        foreach (var population in context.State.Populations)
        {
            var environment =
                context.State.Environment[population.CellIndex];
 
            var resources =
                context.State.Resources[population.CellIndex];
 
            var phenotype = PhenotypeCalculator.Calculate(
                population.Genome);
 
            var environmentalFactor =
                EnvironmentalCalculator.Calculate(
                    environment, phenotype);
 
            var potentialProduction = CalculateProduction(
                phenotype,
                environmentalFactor,
                population.BiomassKg,
                deltaTime);
 
            // Resource consumption must be reconciled
            // through shared cell-level allocation buffers.
            // Do not subtract shared resources directly here.
        }
    }
 
    private static double CalculateProduction(
        Phenotype phenotype,
        double environmentalFactor,
        double biomass,
        double deltaTime)
    {
        return biomass
            * phenotype.PhotosyntheticEfficiency
            * environmentalFactor
            * deltaTime;
    }
}
CalculateProduction es fórmula de prototipo, no modelo metabólico definitivo. La implementación real debe usar reacciones y recursos limitantes.
12.4 Sistema poblacional (esqueleto)
public sealed class PopulationSystem : ISimulationSystem
{
    public void Execute(SimulationContext context, double deltaTime)
    {
        foreach (var population in context.State.Populations)
        {
            if (population.Abundance <= 0)
                continue;
 
            var phenotype =
                PhenotypeCalculator.Calculate(population.Genome);
 
            var growthRate = phenotype.ReproductionRate;
 
            var growth = population.Abundance
                * growthRate
                * deltaTime;
 
            population.Abundance += growth;
        }
    }
}
Este esqueleto no debe utilizarse en juego hasta limitar crecimiento por energía, materia, mortalidad y capacidad de carga.
12.5 Validador
public static class SimulationValidator
{
    public static void Validate(SimulationState state)
    {
        foreach (var resource in state.Resources)
        {
            if (resource.Water < 0 ||
                resource.Oxygen < 0 ||
                resource.CarbonDioxide < 0 ||
                resource.Nitrogen < 0 ||
                resource.Phosphorus < 0)
                throw new InvalidOperationException(
                    "Negative resource quantity detected.");
        }
 
        foreach (var population in state.Populations)
        {
            if (population.Abundance < 0)
                throw new InvalidOperationException(
                    "Negative population abundance.");
 
            if (population.BiomassKg < 0)
                throw new InvalidOperationException(
                    "Negative biomass.");
        }
    }
}

21. Decisiones finales consolidadas
No crear individuos como objetos de simulación: usar poblaciones agregadas con variantes genéticas diferenciadas.
No permitir generación gratuita de recursos: todos los procesos sujetos a balances de materia y energía.
No acoplar el motor a Godot: la simulación debe ejecutarse y validarse independientemente.
La ambición de MARTIS puede ser grande, pero el primer objetivo técnico debe ser pequeño: una región, una población, un organismo, un conjunto limitado de recursos y una simulación reproducible.
El siguiente paso no es redactar otro documento de diseño: es crear el repositorio e implementar Martis.Domain, Martis.Simulation, Martis.Cli y sus pruebas automatizadas, capaces de inicializar y ejecutar una región marciana de 64 × 64.

B.4 Escalas temporales y transformación ambiental
La simulación podrá avanzar desde horas hasta siglos, con pausa y velocidades seleccionables. La duración real de cada proceso dependerá del nivel de abstracción y del paso temporal implementado.
Se distinguen tres niveles de transformación:
Transformación biológica: colonización, biopelículas y modificación de química superficial.
Hábitats regionales soportados tecnológicamente: instalaciones o entornos presurizados que permiten experimentos controlados.
Ingeniería planetaria especulativa: capa avanzada y explícitamente hipotética; no se presentará como una capacidad biológica disponible con tecnología conocida.
